# 文字モンスター（Firebase版）

1文字・色・フォントからモンスターを生み、育てて大会制覇を目指す育成ゲームです。
助手キャラクター「モジカ」が、チュートリアルと日々のアドバイス（右上からスライドインするトースト通知）で案内します。

- 同じ「文字・色・フォント」の組み合わせからは、いつも同じモンスター・同じ初期ステータスが生まれます（決定論的生成）。
- 色で属性（炎・土・雷・草・氷・水・闇・光・無）、フォントで流派（剛流・雅流・柔流・荒流・速流・変流・奇流）が決まります。
- 1日＝朝の餌やり＋行動1つ。7日目デビュー戦、14日目準決勝、21日目決勝。全勝でクリア＆殿堂入り。
- 育てたモンスターは保存・配合・冬眠（凍結保管6スロット）・売却が可能。寿命はなく、負けても死にません。
- Firebaseを設定すると、ほかのプレイヤーが公開したモンスターとのゴーストバトル／ランダムマッチが遊べます。

## 開発方針：単一コードベース＋バックエンドアダプタ方式

- **このプロジェクトが、ゲームの唯一のマスターコードベースです。** 今後の仕様変更・修正はここにだけ入れます（環境ごとの複製は作りません）。
- ゲームエンジン（生成・育成・バトル・配合などの純ロジック）は `src/lib/game.ts`、画面は `src/screens/`（1画面1機能1ファイル）、共通部品は `src/components/`、状態管理は `src/lib/store.tsx`、診断ログは `src/lib/log.ts` にあり、すべて単一実装です。
- 環境によって分岐するのは「データの保存先と公開プールへの接続」だけです。その差分は `src/lib/backend.ts` の **BackendAdapter** インターフェース（状態の保存/読込、公開モンスターの登録/取得、認証）の背後に閉じ込めています。実装は2つだけです。
  1. **LocalAdapter**：localStorageに保存。オンライン機能は利用不可。
  2. **FirebaseAdapter**：Firebase Auth＋Firestore。オンライン機能が有効。
  どちらになるかは `.env` にFirebase設定があるかどうかだけで決まります。
- 機能の可用性はアダプタの **capability フラグ**（`capabilities.publicPool` など）で判定します。LocalAdapter（Firebase未設定）では、殿堂入りゴースト・ランダムマッチ・公開登録のボタンがグレーアウトし、「Firebaseに接続すると遊べるよ」という注記／モジカのトーストで理由を示します。生成・育成・大会・フリーバトル・配合・冬眠・コレクション・売却などの1人プレイ部分は、両環境で完全に同一に動きます。
- 文字数の書記素判定（`Intl.Segmenter`）や診断ログも共通実装1つだけです。環境別の複製はありません。

## そのまま遊ぶ（ローカルモード）

Firebase未設定でも、そのまま単体で遊べます。この場合データはブラウザの localStorage に保存され、対戦相手はサンプルモンスターになります。

```bash
npm install
npm run dev
```

表示されたURL（通常 http://localhost:5173 ）をブラウザで開いてください。

## Firebaseの準備（クラウド保存＆対戦プールを有効化）

### 1. Firebaseプロジェクトを作る

1. [Firebase コンソール](https://console.firebase.google.com/) を開き、「プロジェクトを追加」から新規プロジェクトを作成します（名前は任意）。
2. プロジェクトのトップで「Webアプリ（</>）」を追加し、表示される設定値（apiKey など）を控えます。

### 2. Authenticationを有効化

1. コンソールの「構築 > Authentication > 始める」を開きます。
2. 「Sign-in method」で **匿名** を有効化します（必須：ゲーム開始時に自動で匿名サインインします）。
3. 同じ画面で **Google** も有効化します（任意：プレイヤーが後からGoogleアカウントと連携できるようになります）。

### 3. Firestoreを作成

1. 「構築 > Firestore Database > データベースの作成」を開きます。
2. ロケーションを選んで「本番環境モード」で作成します（ルールは次の手順でこのプロジェクトの `firestore.rules` に置き換わります）。

### 4. 設定値を `.env` に記入

プロジェクト直下で `.env.example` をコピーして `.env` を作り、手順1で控えた値を入れます。

```bash
cp .env.example .env
```

```ini
VITE_FIREBASE_API_KEY=あなたのAPIキー
VITE_FIREBASE_AUTH_DOMAIN=あなたのプロジェクト.firebaseapp.com
VITE_FIREBASE_PROJECT_ID=あなたのプロジェクトID
VITE_FIREBASE_STORAGE_BUCKET=あなたのプロジェクト.appspot.com
VITE_FIREBASE_MESSAGING_SENDER_ID=送信者ID
VITE_FIREBASE_APP_ID=アプリID
```

### 5. デプロイ

Firebase CLI を使ってデプロイします。

```bash
npm install            # 依存パッケージのインストール
npm install -g firebase-tools   # 未インストールの場合のみ
firebase login         # Googleアカウントでログイン
firebase use --add     # 手順1のプロジェクトを選択
npm run build          # dist/ が生成されます
firebase deploy        # Hosting と Firestoreルールがデプロイされます
```

デプロイ後に表示される Hosting URL が、公開されるゲームのURLです。

> ローカルでFirebase接続を確認したい場合は、`.env` を入れた状態で `npm run dev` でも動作します。

## 遊び方の要点

- **生成フロー**：ステップ1で文字を入力（モンスターになるのは最初の1文字だけ。2文字以上入力すると余分が赤くハイライトされ、モジカが知らせて進めません）→ ステップ2で色とフォント → ステップ3の確認画面で「この設定で作成する」を押して初めて誕生します。
- **餌と なつき度**：安い餌はなつき度が下がります。低すぎると特訓・自主練をサボることがあります。
- **コンディション**：低いと成長が鈍り、バトルも不利になります。休息で回復。
- **配合**：保存済み2体を消費します。文字はどちらかを継承、色は中間色±個体差、ステータスは項目ごとに抽選され、強い親の総合力が下限保証されます。
- **冬眠（凍結保管）**：育成途中の子を最大6体まで氷漬けで保管。手元は常に1体だけです。
- **みんなのモンスター**：殿堂入り・保存時に「公開する」を選ぶと公開プールに登録されます（`publicMonsters`）。他人の子とはゴーストバトル／ランダムマッチで対戦でき、報酬は1日5回までです。
- **バトル演出**：観戦画面では、攻撃側の文字が相手へ突っ込み、被弾側が点滅＋シェイクします。ダメージ数字がポップし、ヒット時は攻撃側の属性色のフラッシュと粒子が出ます。必殺技はカットイン（文字の拡大＋技名の帯）＋画面シェイク付きで、行ごとに表示テンポも変わります（必殺・会心・決着は長め）。試合前にはVS導入（両者の属性・流派・総合力比較）があり、勝利時は紙吹雪、HPバーには遅れて減る残像バーが付きます。
- **バランス**：大会の相手は手元の総合力に合わせて強くなります（目標総合力＝従来の基準値と「手元の総合力×倍率（0.82／0.94／1.02）」の大きい方）。必殺ゲージは控えめで、必殺は1戦に合計1回あるかないかの見せ場です。モジカの実況は相性の有利不利や会心・必殺・回避・連撃にも反応します。
- **ランダムイベント**：試合日でない日は、行動後に約18%の確率で小さなイベント（コツを掴む／差し入れ／落とし物のお礼／いい夢／近所の子と模擬戦）が起き、結果画面とトーストに表示されます。

## 診断ログ

メニューの「診断ログ」から、アプリ内の診断ログを閲覧できます。文字入力ごとの生文字列・コードポイント一覧・書記素（grapheme）分割結果・文字数とオーバー判定のほか、画面遷移、作成、ターン、バトル、エラーが時刻付きで記録されます（最大400件、この端末内に保存）。「ログをコピー」ボタンで全件をテキストとしてコピーできます。

文字数は `Intl.Segmenter`（granularity: 'grapheme'）の書記素クラスタ単位で数えます。そのため ☢️（U+2622＋異体字セレクタ U+FE0F）、👨‍👩‍👧（ZWJ連結）、🇯🇵（国旗ペア）、か＋結合濁点なども、それぞれ1文字として扱います。

## データの置き場所

| データ | 場所 |
| --- | --- |
| 自分のゲーム状態 | FirebaseAdapter：Firestore `users/{uid}`（本人のみ読み書き可）＋初回描画用ローカルキャッシュ ／ LocalAdapter：localStorage のみ |
| 公開モンスター | Firestore `publicMonsters/{uid}_{monsterId}`（誰でも閲覧可、登録・変更・削除は持ち主のみ） |
| ゲーム本体 | Firebase Hosting（`dist/`） |

セキュリティルールは `firestore.rules` に同梱されています。公開プールはフィールド検証付きで、本人のモンスター以外は登録・改変できません。

## 制限事項

- 実際のFirebaseプロジェクトへの接続確認は、デプロイ後にしか行えません（このZIPにはあなたのFirebase設定値は含まれません）。
- ゴーストバトルは相手モンスターのスナップショットとの対戦です。リアルタイム対戦ではありません。
- 育成データの正当性検証はクライアント＋ルールの範囲で行われ、Cloud Functionsによるサーバー側検証は含まれません（ランキング等を厳密に競う用途では追加実装を検討してください）。
